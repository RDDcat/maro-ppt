03시그니처 장치

이 일곱 개가 “이 덱처럼 보이는가”를 결정합니다.

① 형광펜 하이라이트 — 한 장에 한 번

둘은 똑같아 보이는데
왜 하나는 수정이 더 쉬울까?

.accent{background:linear-gradient(transparent 64%,var(--lime) 64%)}

② ③ 결론 밴드 — 도해는 반드시 한 줄로 닫는다

화면 코드에 직접 적힌 디자인 값0곳
기준은 화면 수가 아니라 반복되는 결정입니다.

④ 프롬프트 블록 — 덱당 2개까지

USE UI UX PRO MAX
현재 프로젝트에 30분 안에 적용할 수 있는 최소 디자인 시스템을 구축하고 실제 UI에 적용해줘.
기존 데이터와 기능 유지 · 새 프레임워크 금지 · 현재 화면에 필요한 만큼만

⑤ 화살표 흐름 — 마지막 칸만 잉크

공통 규칙 사용→같은 UI 재사용→한곳만 수정

⑥ 숫자 히어로 — 그래프 대신 큰 숫자 둘

124→22

흩어진 디자인 값 → 공통 규칙

색 8→2 · 모서리 28→4 · 여백 55→10 · 글자 33→6

⑦ 스크린샷 프레임 — 덱에서 그림자는 여기 하나뿐

BEFORE · opacity .52 + grayscale
AFTER · 원본

두 장을 나란히 놓고 한쪽을 죽이는 것으로 “이쪽을 보라”를 말합니다. 화살표나 빨간 동그라미를 그리지 않습니다.

04컴포넌트

카드는 radius 0 · 그림자 없음. 선으로만 존재합니다.

① 카드 .top

병렬 항목 3개일 때. 상단 5px 잉크 바.

② 기본 카드

1px 선. 그 안에 예시 UI를 그릴 수 있습니다.

③ 사각 칩 — 폐기

.chip / .chips 는 쓰지 않습니다. 주제를 태그로 나열하면 관계가 안 보이고 단어만 훑게 됩니다. 번호 목록·비교 카드·표로 대체합니다.

번호 단계 — 원형 번호는 여기서만

01
현재 화면·CSS 분석직접 적힌 디자인 값과 UI 구조 확인
02
이미 반복된 것 발견비슷한 색·간격·버튼 패턴 찾기
03
공통 규칙으로 묶기토큰과 컴포넌트로 정리

06하지 않는 것

✕ 금지

  • 태그·배지 나열 (.chip / .chips) — 폐기
  • 그라데이션 배경 (형광펜만 예외)
  • 카드 그림자 — 그림자는 스크린샷 1곳뿐
  • 장식용 이모지 ✨🚀💡🎯
  • 강조색 2개 이상
  • 라임 위 흰 글자 · 색 위 색 글자
  • 흰색(#fff) 덱 배경
  • 웹폰트 · CDN · 외부 이미지
  • 자동 줄바꿈에 맡긴 한글 제목

✓ 대신 이렇게

  • 단색 라벨 대신 문장으로
  • 단색 면 + 1px 선
  • 오프셋 그림자 17px 17px 0 #dce4c5 하나
  • 기능 기호만 → ↗ ✓ ① 01
  • 라임 하나 + 회색조
  • 라임 위에는 잉크 글자
  • 아이보리 #f4f1e9
  • 시스템 폰트 · base64 인라인 이미지
  • 모든 줄에 .nowrap

07완료 전 체크

✓배경이 #f4f1e9 인가 (흰색이 아닌가)
✓제목마다 .accent 가 한 번씩만 걸렸는가
✓모든 제목 줄이 .nowrap 으로 감싸였는가
✓카드·밴드의 radius 가 0 인가
✓태그(.chip / .chips)를 쓰지 않았는가
✓라운드·파랑·알약이 예시 UI 안에만 있는가
✓그림자가 스크린샷 프레임 외에 없는가
✓각 도해가 결론 밴드로 닫히는가 (밴드 합계 6개 이하)
✓프롬프트 블록이 2개 이하인가
✓외부 요청 0건인가
✓900px · 600px 로 줄여도 1단으로 접히는가
