# 몸값 올리는 PPT 제작

발표 덱 하나를 **인터뷰 → 확장 → 생성 → 수정** 순서로 만든다.

핵심은 **확장**이다. 사용자가 준 항목을 슬라이드로 1:1 옮기지 않는다.
각 항목이 청중을 어디까지 데려가야 하는지 판단해서, 그만큼의 장으로 펼친다.

**두 축을 섞지 않는다.**

| 축 | 정하는 것 | 어디에 |
|---|---|---|
| **내용** | 무엇을 몇 장으로 말하는가 | 이 문서 2절 (스타일·유틸과 무관) |
| **스타일** | 덱이 어떻게 보이는가 | `styles/{스타일}/style.md` |
| **유틸** | 슬라이드 안에 어떤 현실 화면을 재현하는가 | `utils/{유틸}/util.md` |
| **모션** | 슬라이드 안의 그래픽이 어떻게 움직이는가 | `motions/{모션}/motion.md` |

스타일은 인터뷰에서 **고르고**, 유틸·모션은 확장 중에 스킬이 **찾아서 집는다**(없으면 만든다).

**정해진 자리는 없다.** "몇 번째 장에는 무엇이 온다"는 규칙을 두지 않는다.
템플릿·유틸·모션은 *꺼내 쓰는 부품*이고, 어느 장에 무엇을 놓을지는 그 장이 하려는 말과 사용자의 요청이 정한다.

---

## 1. 인터뷰 — 한 번에 하나씩 묻는다

**질문을 한꺼번에 쏟지 않는다.** 앞의 답이 뒤의 질문을 바꾸기 때문이다.
사용자가 첫 요청에서 이미 준 항목은 건너뛰고, 확인만 한 줄로 한다.

### 1단계 — 핵심 메시지

> "이 발표를 듣고 난 사람이 딱 한 문장만 기억한다면, 그게 뭐였으면 좋겠어요?"

**주제가 아니라 주장이어야 한다.** 판정법: 반대 문장을 만들어 본다.

| 답 | 반대 문장 | 판정 |
|---|---|---|
| "토큰에 대해서" | (반대가 없음) | ✗ 주제다. 다시 묻는다 |
| "토큰을 모르면 API 비용이 10배로 샌다" | "토큰을 몰라도 비용은 안 샌다" | ✓ 주장이다 |

주제로 답하면 되묻지 말고 **후보 2~3개를 만들어 고르게 한다.** 물어보기만 하면 같은 답이 온다.

핵심 메시지는 덱 전체의 척추다. 뒤의 모든 판단이 여기에 걸린다.

### 2단계 — 후킹 제목

> "표지에 걸 제목이 있나요? 없으면 제가 세 개 뽑아 드릴게요."

**후킹은 표지 한 장에서만 한다.** 본문 슬라이드 제목은 후킹하지 않는다.
장마다 후킹을 걸면 장끼리 경쟁해서 덱 전체가 난잡해진다.

없다고 하면 핵심 메시지에서 **서로 다른 방식으로 세 개**를 만들어 보인다.

| 방식 | 예 |
|---|---|
| 손실 | 모르면 새는 돈, 토큰 |
| 숫자 | 같은 질문, 비용은 10배 |
| 오해 | 토큰은 글자 수가 아니다 |

- 표지 부제는 **핵심 메시지를 그대로 또는 한 겹 압축해서** 쓴다.
- 덱 마지막 장의 결론 밴드에 핵심 메시지를 **다시 한 번 문장 그대로** 놓는다. 표지와 수미상관이 된다.

### 3단계 — 슬라이드 구성

> "다룰 항목을 순서대로 적어 주세요. 한 줄씩, 거칠어도 됩니다."
> "적어 주신 항목이 슬라이드 한 장씩이 되는 건 아니고, 각 항목을 설득 구조로 펼쳐서 만들 거예요."

**미리 알린다.** 알리지 않으면 생성 결과를 보고 "내가 말한 것과 다르다"가 된다.

- 항목이 **2개 이하**면: 다룰 범위가 좁다. 무엇을 더 넣을지 되묻거나, 짧은 덱(6~8장)으로 가겠다고 말한다.
- 항목이 **12개 초과**면: 주제를 둘로 쪼개자고 제안한다. 한 덱에 다 넣으면 어느 것도 안 남는다.

### 4단계 — PPT 스타일

**묻기 전에 `styles/` 를 실제로 읽는다.** 목록을 외워서 답하지 않는다.

```bash
for f in styles/*/style.md; do sed -n '2,6p' "$f"; echo; done
```

각 `style.md` 의 frontmatter 에 `label`(이름) · `tagline`(인상) · `fit`(어울리는 자리)이 있다.

| 등록된 스타일 수 | 할 일 |
|---|---|
| **1개** | 묻지 않는다. "{label} 스타일로 만들게요" 한 줄만 알린다 |
| **2개 이상** | `label` 과 `tagline` 을 나란히 보여 주고 고르게 한다 |

고른 스타일의 **`style.md` 를 끝까지 읽고 나서** 확장(2절)에 들어간다.
도해 카탈로그가 그 문서에 있고, 확장할 때 그 표에서 고르기 때문이다.

**유틸·모션은 묻지 않는다.** 확장 중에 필요하다고 판단되면 스킬이 찾아서 넣고,
생성 후 요약표에 어느 장에 무엇을 썼는지 표시한다(2-5·3절).
사용자가 먼저 말했으면("카톡 대화로 보여 줘", "숫자가 올라가게") 그 요청이 판단보다 앞선다.

### 5단계 — 나머지 (한 번에 묻는다)

| 항목 | 기본값 |
|---|---|
| 듣는 사람 | 비개발자 |
| 저장 위치·파일명 | 현재 작업 디렉터리 / `{후킹 제목}.html` |
| 헤더 좌상단 라벨(BRAND) | 주제의 영문 대문자 한 단어 |
| 스크린샷·수치 자료 | 없음 (없으면 증거 유형 장을 빼고 짧게 간다) |

장수는 **묻지 않는다.** 내용이 정한다(2-3).

## 2. 확장 — 항목을 설득 구조로 펼친다

이 절이 이 스킬의 핵심이다. HTML을 열기 전에 머릿속에서 끝낸다.
**스타일이 무엇이든 이 절은 똑같이 적용된다.**

### 2-1. 항목의 유형을 먼저 판별한다

사용자가 준 한 줄이 **무엇을 하려는 문장인지** 정한다. 유형이 사이클을 정한다.

| 사용자가 쓴 말 | 유형 |
|---|---|
| "X의 정의", "X란 무엇인가", "X 설명" | **개념** |
| "A와 B의 차이", "A vs B", "헷갈리는 것" | **대조** |
| "어떻게 쓰는가", "사용법", "세팅" | **절차** |
| "왜 필요한가", "효과", "근거" | **근거** |
| "무슨 도구", "추천 툴" | **도구** |
| "사례", "우리가 해 본 것", "실제로" | **사례** |
| "정리", "다음 할 일", "마무리" | **전환** |

### 2-2. 유형별 설득 사이클

각 칸이 슬라이드 후보다. **모든 칸을 채우지 않는다.** 청중이 이미 아는 칸은 뺀다.

| 유형 | 사이클 (→ 순서대로) |
|---|---|
| **개념** | 왜 알아야 하나(겪는 불편) → 정의 한 문장 → 실물 예시 → 경계(이건 아니다) |
| **대조** | 겉보기엔 같다 → 갈라지는 지점 하나 → 어느 쪽을 고르나(기준) |
| **절차** | 준비물 → 단계 3개 → 그대로 칠 프롬프트 → 결과 |
| **근거** | 주장 → 숫자·화면 증거 → 나올 만한 반론 하나 처리 |
| **도구** | 문제에 필요한 조건 → 도구와 출처 링크 → 고르는 기준 |
| **사례** | before(문제 상태) → 무엇을 바꿨나 → after(숫자) |
| **전환** | 여기까지의 요약 → 오늘 할 수 있는 첫 걸음 → 별도로 고민할 것 |

> 예 — 사용자 입력 `토큰의 정의를 설명` (minimal 스타일)
>
> | 장 | 유형 칸 | 제목 | 말하려는 관계 → 도해 |
> |---|---|---|---|
> | 1 | 왜 알아야 하나 | 같은 질문에 다른 요금 | 수치 대비 → `.stat` |
> | 2 | 정의 | 토큰은 모델이 읽는 조각 | 순서·인과 → `.flow` |
> | 3 | 실물 예시 | 한국어와 영어의 토큰 수 | A와 B의 차이 → `.duo` |
>
> "경계" 칸은 뺐다. 비개발자 청중에게 "토큰이 아닌 것"은 아직 필요 없다.
>
> **먼저 "말하려는 관계"를 정하고, 그 다음에 스타일의 카탈로그에서 도해를 고른다.**
> 순서를 뒤집으면 예쁜 도해에 내용을 끼워 맞추게 된다.

### 2-3. 장수는 내용이 정한다

한 장에 담는 단위는 **메시지 하나**다. 청중이 "그래서?"를 한 번만 물으면 되는 크기.

**쪼개는 신호** — 하나라도 걸리면 두 장으로 나눈다.

- 도해가 두 개 필요하다
- 리드 문장이 두 문장이 된다
- 나열 항목이 6개를 넘는다
- 정의와 예시를 같은 화면에서 봐야 한다
- 숫자와 그 숫자의 해설을 같이 봐야 한다

**합치거나 빼는 신호** — 하나라도 걸리면 앞 장에 흡수하거나 지운다.

- 도해 없이 한 줄로 끝난다
- 앞 장의 결론 밴드와 같은 말을 한다
- 그 장을 빼도 논리가 이어진다
- 사용자가 시킨 항목이라 넣었을 뿐, 핵심 메시지 쪽으로 한 칸도 못 올라간다

**전체 분량**: 9~15장이 정상이다. 20장을 넘으면 주제를 쪼갠다.
6장 미만이면 각 항목의 사이클에서 뺀 칸을 다시 본다.

### 2-4. 덱 전체의 순서 — 고정 뼈대가 없다

**장 순서를 미리 정해 두지 않는다.** 순서는 사용자가 준 항목 순서와 2-2 사이클이 정한다.
"2번째 장은 도입", "결과는 n-1번째" 같은 자리 규칙을 만들지 않는다.

지키는 것은 둘뿐이다.

- **표지가 맨 앞이다.** 후킹 제목 + 핵심 메시지(부제). 덱이라는 형식 자체의 약속이다.
- **덱이 핵심 메시지로 닫힌다.** 마지막 장이 무엇이든(요약·다음 할 일·사례) 그 결론 밴드에 핵심 메시지를 문장 그대로 놓는다.
  표지와 수미상관이 된다. 별도의 "마무리 장"을 꼭 만들라는 뜻은 아니다.

- 청중이 아는 불편을 먼저 꺼내는 게 설득에 유리하면 앞에 두되, 그건 첫 항목의 "왜" 칸이 거기 오는 것이지 자리가 정해진 것이 아니다.
- 목차 장은 **12장을 넘을 때만** 넣는다. 짧은 덱에서는 흐름을 끊는다.
- 본론에서 유형이 바뀌는 지점(개념 → 절차 등)은 앞 장의 결론 한 줄로 잇는다. 따로 전환 장을 만들지 않는다.

### 2-5. 템플릿을 찾는다 — 없으면 만든다

장마다 **"이 장이 하려는 말"**(2-2 칸 + 관계)이 정해졌으면, 그 말을 가장 잘 보여 줄 부품을 **찾는다.**
부품은 세 서랍에 있다. 순서대로 본다.

| 서랍 | 무엇 | 매칭 키 |
|---|---|---|
| 스타일의 도해 카탈로그 | 관계를 추상화한 정적 그림 (`.flow` `.duo` `.stat` …) | `style.md` 3절 "말하려는 것" |
| `utils/` | 현실 화면의 재현 (카톡, 브라우저 창 …) | `util.md` 의 `when` |
| `motions/` | 움직이는 그래픽 (제목 각인, 숫자 올리기, 프롬프트 치기 …) | `motion.md` 의 `shows` |

**묻기 전에 실제로 읽는다.** 목록을 외워서 답하지 않는다.

```bash
for f in utils/*/util.md motions/*/motion.md; do sed -n '2,8p' "$f"; echo; done
```

- 맞는 게 있으면 집는다. **그 부품이 어느 장에 오는지는 정해져 있지 않다** — 카톡 화면은 첫 장 뒤에도, 사례 중간에도, 마지막에도 올 수 있다.
- 사용자가 요청한 화면·움직임이 있으면 그 서랍부터 찾는다.
- **맞는 게 없으면 만든다.** 그 서랍의 README("새 유틸 추가하는 법" / "맞는 모션이 없으면 만든다")를 따라 덱 안에 직접 만들고,
  쓸 만하면 생성 후 "이걸 `utils/`(`motions/`)에 등록할까요?"라고 한 번 묻는다. 묻지 않고 스킬 폴더에 쓰지 않는다.
- **새로 만들 때 비슷한 기존 클래스를 덮어써서 만들지 않는다**(`.frame.my-fig` 처럼). 덮어쓴 클래스의 규칙 —
  자르는 높이, `object-position:top left` 같은 정렬 — 이 그대로 따라와 화면이 한쪽으로 쏠린다. 새 클래스로 처음부터 쓴다.

#### 유틸 — 그 장면이 원래 그 화면에서 벌어졌는가

**기본값은 도해다.** 유틸은 도해로는 안 되는 이유가 분명할 때만 집는다.
"재현하면 생생하겠다"는 이유가 되지 않는다 — 그 기준이면 불편·문제 제기 장(대개 표지 바로 뒤)이 매번 유틸이 된다.

| 그 장이 하려는 것 | 무엇을 쓰나 |
|---|---|
| A와 B가 **다르다**를 말한다 | 도해 (스타일 카탈로그) |
| 개념을 **정의**한다 | 도해 |
| 수치를 **비교**한다 | 도해 |
| 청중이 겪는 **불편·문제**를 꺼낸다 | 도해 (`.stat` · `.duo` …) — 아래 두 질문을 통과할 때만 유틸 |
| 그 일이 **특정 제품 화면 안에서** 벌어졌고, 그 화면 자체가 증거다 | **유틸** |

유틸을 집기 전에 두 질문에 **둘 다 "예"** 여야 한다.

1. **그 장면이 원래 그 화면에서 벌어졌는가?** 카톡 유틸이라면, 사람과 사람이 메신저로 주고받은 대화여야 한다.
   혼자 겪는 불편, 회의·대면에서 생긴 일, 도구 사용 중의 문제는 카톡이 아니다.
2. **내용이 사용자 자료에 있거나, 지어내지 않고 쓸 수 있는가?** 대사를 꾸며야만 화면이 채워지면 도해로 간다.

사용자가 그 화면을 먼저 요청했으면("카톡 대화로 보여 줘") 두 질문 없이 쓴다.

**상한 — 한 덱에 유틸 2개까지.** 같은 유틸은 한 번만 쓴다.
세 번째부터는 밈이 아니라 습관으로 보인다. 밴드 6개 규칙과 같은 정신이다.

유틸을 집었으면 그 `util.md` 를 끝까지 읽고 CSS와 마크업을 가져온다.
**결론 밴드로 닫는 것은 유틸도 똑같다.** 화면만 놓고 넘어가지 않는다.

#### 모션 — "생기는 순서"가 메시지인가

모션은 도해·유틸 **위에 거는 것**이다. 이미 고른 부품(`.flow`, `.stat`, `.prompt`, `.kakao` …)이
*어떤 순서로 생기는지* 자체가 그 장의 말일 때만 건다.

| 그 장이 하려는 것 | 모션 |
|---|---|
| 이 한 문장을 기억하라 | `kinetic-title` |
| 이 순서로 넘어간다 | `flow-step` |
| 하나씩 쌓인다 · 대화가 오간다 | `stagger` |
| 이만큼 바뀌었다 | `count-up` |
| 이걸 그대로 친다 | `typing` |
| 무엇이 얼마나 큰가 (3~7개) | `bar-grow` |
| 이 길로 계속 흘러간다 | `packet-flow` — 반복 |
| 한 바퀴로 끝나지 않는다 | `cycle` — 반복 |
| 관계가 정적이다(A와 B는 다르다, 구성요소 셋) | 걸지 않는다 |

**표지에는 걸지 않는다.** 표지는 발표 전에 띄워 두는 화면이라 움직임을 아무도 못 본다.

**반복은 대상이 실제로 계속 돌아갈 때만.** 대부분의 모션은 한 번 움직이고 멈춘다. 파이프라인·루프처럼
"계속 돌아가는 것" 자체가 메시지일 때만 반복이 있는 모션을 고른다. 반복이 하나도 없는 덱이 정상이다.

`bar-grow` `packet-flow` `cycle` 은 그래픽(CSS·마크업)까지 모션이 가져온다. 도해 카탈로그에 그림이 없어도
그 관계를 그릴 수 있다 — `motion.md` 의 CSS 덩이를 `<style>` 맨 아래에, 마크업을 그 장에 넣는다.

**상한 — 한 장에 1개, 한 덱에 4장까지.** 사용자가 더 원하면 따른다.
원칙(단일 콘셉트·덱 토큰 색·금지 목록·2초 안팎·시간 함수·끝 장면 = 원래 마크업)은 `motions/README.md` 에 있다.

### 2-6. 확장 결과를 스스로 점검한다 (생성 직전)

**핵심 메시지 사다리.** 각 장의 결론 한 줄을 세로로 적어 본다.
위에서 아래로 읽었을 때 핵심 메시지에 한 칸씩 가까워져야 한다.
제자리걸음인 장은 뺀다. 이 점검을 거른 덱은 장은 많은데 남는 게 없다.

```
□ 각 장이 메시지 하나만 말하는가
□ 결론 한 줄을 이어 읽으면 핵심 메시지로 수렴하는가
□ 후킹이 표지 한 장에만 있는가
□ 사용자가 준 항목이 전부 어딘가에 반영됐는가 (뺐다면 왜 뺐는지 말할 수 있는가)
□ 같은 도해 유형이 세 번 연속 나오지 않는가
□ 유틸이 2개 이하이고, 각각 그 장면이 원래 그 화면에서 벌어진 장에 놓였는가 (안 쓴 덱이 정상이다)
□ 표지에 모션이 없고, 모션이 4장 이하(반복은 2장 이하)이고, 각각 "생기는 순서"가 메시지인 장에 걸렸는가
□ "몇 번째 장이라서" 놓은 부품이 없는가 — 전부 그 장의 말 때문에 놓였는가
```

## 3. 생성

1. 고른 스타일의 `styles/{스타일}/template.html` 을 **5단계에서 정한 경로**로 복사한다.
2. 템플릿의 `<section class="slide">` 들은 **순서가 아니라 견본**이다(주석이 `견본 · 상황` 처럼 이름만 달고 있다).
   2절에서 정한 장 순서대로 견본을 **골라 복제·배치**하고 `{중괄호}` 자리를 채운다. 안 쓰는 견본은 통째로 지운다.
   같은 견본을 여러 번 써도 된다. 헤더 분모는 스크립트가 자동으로 센다.
   도식(`.dg`) 장을 안 쓰면 그 장만 지운다. 도식 스크립트는 남겨 둔다 — 캔버스가 없으면 아무것도 안 한다.
3. 유틸을 쓰기로 했다면 그 `util.md` 의 CSS 덩이를 **`<style>` 맨 아래에** 붙인다.
   스타일 고유 CSS 뒤에 와야 `.card p` 같은 규칙을 덮는다.
   모션을 쓰기로 했다면 그 요소에 `class="mo" data-motion="{이름}"` 을 붙이고, `motion.md` 의 JS 덩이를
   템플릿 끝 `window.MOTIONS={};` 바로 아래에 붙인다. 모션 재생 스크립트는 고치지 않는다.
4. 체크리스트를 **두 개 다** 돌린다 — 스타일의 `style.md` 것과 이 문서 5절 공통 요건.
5. **저장 서버로 열어 준다** — `open "{파일}"` 로 열지 않는다. file:// 로 열면 편집이 바로 저장되지 않는다.
   ```bash
   python3 ~/.claude/skills/maro-ppt/tools/serve.py --open "{파일}"
   ```
   서버가 없으면 띄우고(127.0.0.1:8765), 덱을 브라우저로 연다. 이미 떠 있으면 그대로 쓴다.
   이렇게 열면 **사용자가 고치는 즉시 원본에 저장되고, 에이전트가 고친 것도 열린 탭에 바로 반영된다.**
6. **장별 한 줄 요약 표를 함께 출력한다.** 사용자가 고칠 장을 손가락으로 짚을 수 있어야 한다.
   **유틸·모션을 쓴 장은 반드시 표시한다.** 묻지 않고 넣었으니 표에서라도 보여야 뺄 수 있다.

   ```
   01 표지    모르면 새는 돈, 토큰
   02 정의    토큰은 모델이 읽는 조각       .flow        ◆ flow-step
   03 예시    한국어와 영어의 토큰 수       .duo
   04 사례    요금 폭탄을 맞은 날           ★ kakao-chat ◆ stagger
   05 구조    요청이 모델까지 가는 길       .dg  ✎ 도식 편집
   06 결과    같은 질문, 비용은 10분의 1    .stat        ◆ count-up
   ```

   모션을 쓴 장이 있으면 한 줄 덧붙인다: "◆ 장은 들어갈 때 한 번 움직여요. R 을 누르면 다시 재생돼요." 

   도식 장이 있으면 한 줄 덧붙인다: "도식은 [편집]을 켜고 그 장에서 박스를 끌어 고칠 수 있어요." 

7. "몇 번 장이 마음에 안 드는지 말해 주세요"로 닫는다. 수정은 그 장만 고친다.
   유틸이 과하다고 하면 그 장을 스타일의 도해로 되돌린다. 모션이 과하다고 하면 `class="mo" data-motion` 만 지운다(끝 장면이 원래 마크업이라 나머지는 그대로다).

## 5. 모든 스타일이 지켜야 할 공통 요건

새 스타일 템플릿을 만들 때도, 덱을 생성한 뒤에도 이것을 확인한다.

```
□ 외부 요청 0건인가 (웹폰트·CDN·http 이미지 없음)
□ 푸터에 [편집] 버튼과 편집 스크립트가 살아 있는가
□ --zoom 과 [ ] 배율 스크립트가 살아 있는가
□ 편집 관련 요소(편집 CSS·푸터 도구·편집 스크립트 2개)에 data-editor 가 붙어 있는가
□ 배율·장 넘기기·도식 보기 스크립트에는 data-editor 가 없는가 (편집 기능 삭제 뒤에도 남아야 한다)
□ 글자가 SVG <text> 가 아니라 편집 가능한 HTML 안에 있는가
□ 헤더 장수가 자동으로 세어지는가
□ 900px·600px 로 줄여도 1단으로 접히는가
```

```bash
f="{만든 파일}"
grep -nE 'https?://(fonts|cdn|unpkg|jsdelivr)' "$f"   # 비어야 정상
grep -c 'id="edit"'               "$f"   # 1 이어야 정상 (편집 버튼)
grep -c 'scale(var(--zoom'        "$f"   # 3 이어야 정상 (.slide + keyframes 2줄)
grep -o '<text'                   "$f" | wc -l   # 0 이어야 정상 (SVG 글자 금지)
grep -oE '<(style|div|script)[^>]* data-editor>' "$f" | wc -l   # 4 이어야 정상 (편집 CSS · 푸터 도구 · 편집 스크립트 2)
grep -c 'id="final"'              "$f"   # 1 이어야 정상 (편집 기능 삭제 버튼)
grep -c 'window.MO='              "$f"   # 1 이어야 정상 (모션 재생 — data-editor 없이)
grep -o 'data-motion="[^"]*"'     "$f" | sort | uniq -c   # 쓴 모션마다 MOTIONS['이름'] 정의가 붙어 있어야 한다
```

### 5-1. 인라인 편집 — 만들 때 빼지 않는다 (빼는 건 발표자가 5-3 으로)

| 동작 | 방법 |
|---|---|
| 편집 켜기/끄기 | 푸터 `[편집]` 또는 `E` (한글 입력 상태의 `ㄷ` 도 먹는다) |
| 고치기 | 글자를 클릭하고 그대로 타이핑 (서식·구조는 안 바뀐다) |
| **저장** | **저장 서버로 열었으면 고치는 즉시 원본에 저장된다**(0.4초 뒤). 버튼이 필요 없다 |
| 저장 (file:// 로 열었을 때) | `[저장]` 또는 `⌘S` (한글 입력 상태의 `⌘ㄴ` 도 먹는다) — 처음 한 번만 파일을 묻고, 그 뒤로는 자동 저장 |
| 되돌리기 | `[원래대로]` |

**저장 서버 모드 (`tools/serve.py --open` 으로 연 경우 — 기본)**

- 고칠 때마다 덱이 서버에 PUT 해서 원본을 덮어쓴다. 파일 고르기 창이 없다.
- 열린 탭이 1.5초마다 파일을 확인한다. **에이전트가 파일을 고치면 탭이 알아서 새로고침**해 그 변경을 받는다(보던 장은 유지).
- 저장 직전에 에이전트가 고쳤으면 서버가 409 로 거절하고, 탭은 새로고침한 뒤 사용자 편집을 원래 글자 기준으로 다시 붙여 저장한다.
- 서버는 127.0.0.1 에서만 듣고, 홈 폴더 아래 `.html` 만 읽고 쓴다. 끄기: `serve.py --stop`

**file:// 로 연 경우 (서버 없이)**

- 파일 핸들은 IndexedDB 에 남아 **브라우저를 껐다 켜도 유지된다.**
- **한 번 저장한 뒤로는 자동 저장된다.** 고칠 때마다 1초 뒤 원본 파일에 바로 쓴다. 에이전트는 디스크만 보므로, 저장 안 한 편집은 에이전트에게 없는 것과 같다.
- **처음 저장할 때 원본이 아닌 새 파일을 고르면 경고한다.** 비어 있는 파일 = 사본이다. 사본에 저장하면 에이전트가 원본을 고칠 때 편집이 묻힌다.
- **탭을 연 뒤 파일이 밖에서 바뀌었으면(에이전트 수정) 덮어쓰기 전에 묻는다.** 자동 저장은 멈춘다. 새로고침하면 된다.
- **저장 안 한 편집은 "원래 글자"와 함께 브라우저에 남는다.** 새로고침하면 원래 글자로 자리를 다시 찾아 붙인다.
  에이전트가 같은 자리를 고쳤으면 에이전트 쪽을 남기고, 사용자 편집은 덮어쓰지 않고 따로 보관한 뒤 알린다(콘솔 `maroLost`).
- 저장 안 한 편집이 있으면 탭을 닫을 때 묻는다.
- 편집 중에는 `←` `→` 로 장이 넘어가지 않는다(`e.target.isContentEditable` 로 막아 둠).
- 글자는 반드시 편집 대상 선택자 안에 두어야 한다:
  `h1 h2 h3 p small figcaption .link .band .flow span .flow strong .steps>div .pairs>div .breakdown span .stat .prompt`
- **SVG 안에 `<text>` 로 글자를 넣지 않는다.** SVG는 도형만, 글자는 그 위에 얹는 HTML(`position:absolute`)로.
- 편집기는 서식이 아니라 **글자만** 바꾼다(`plaintext-only`).

**덮어쓰기가 안 될 때** — File System Access API 가 없는 Safari·Firefox 에서 file:// 로 열면
자동으로 내려받기로 떨어지고 푸터에 이유가 뜬다. 저장 서버로 열면 어느 브라우저든 바로 저장된다.

```bash
python3 ~/.claude/skills/maro-ppt/tools/serve.py --open "{파일}"
```

### 5-2. 도식 편집 — 도식 장에서만

도식(`.dg`)은 평소에 그냥 그림이다. 떠 있는 버튼이 없다.
**[편집]을 켠 채 도식 장에 오면** 푸터에 도식 도구가 붙고, 장을 넘기면 사라진다.

| 동작 | 방법 |
|---|---|
| 박스 옮기기 | 끈다 (10px 격자) · 고른 뒤 `←↑→↓` 1px, `⇧` 10px |
| 크기 | 고른 박스의 오른쪽 아래 네모를 끈다 |
| 글자 | 박스 글자를 더블클릭 |
| 화살표 라벨 | 화살표나 라벨을 더블클릭 (비우면 지운다) |
| 박스 추가·복제·삭제 | `[박스]` · `[복제]`/`⌘D` · `[삭제]`/`Delete` |
| 화살표 잇기 | 출발 박스를 고르고 `[연결]` → 도착 박스를 누른다 |
| 모양 | `[모양]` 박스: 흰→잉크→라임 · 화살표: 실선↔점선 / `[휘기]` 화살표: 직선→오른쪽→왼쪽 |
| 되돌리기 | `⌘Z` / `⇧⌘Z` — **그 캔버스만** 되돌린다 |
| 저장 | 덱의 `⌘S` 하나 (글자 편집과 같은 파일 핸들) |

- 박스를 고른 동안 `←→` 는 박스를 움직인다. `Esc` 로 선택을 풀면 다시 장이 넘어간다.
- 저장하지 않은 도식 변경은 브라우저에 남아 다시 열어도 복구된다. `[원래대로]` 는 도식도 되돌린다.
- 도식 안 글자는 덱의 글자 편집 대상이 아니다(`.dg` 는 제외된다). 도식 편집기가 맡는다.

### 5-3. 편집 기능 삭제 — 마지막 장에서

**마지막 장에서만** 푸터에 `[편집 기능 삭제]` 가 뜬다. 누르면 `data-editor` 가 붙은 것을 전부 걷어낸
발표용 HTML 을 **새 파일**(`{이름}-발표용.html`)로 저장한다. 원본을 덮어쓰려면 저장 창에서 원본을 고른다.

| 남는 것 | 빠지는 것 |
|---|---|
| 장 넘기기 · `[ ] \` 배율 · 도식 그림(화살표 다시 그리기·폭 맞춤) | 글자 편집 · 도식 편집 · 저장 · 편집 CSS · 푸터 도구 버튼 |

- 발표용 파일은 다시 편집할 수 없다. **원본을 지우지 말라고** 한 번 말해 준다.
- 원본이 없어졌는데 고쳐야 하면: 템플릿에서 `data-editor` 가 붙은 네 덩이(편집 CSS · 푸터 `.tools` · 스크립트 2개)를
  같은 자리에 다시 넣는다.

### 5-4. 강의 중 화면 배율 — `[` `]`

강의실 뒷자리에서 글씨가 작을 때 키보드로 슬라이드를 키우고 줄인다. 버튼도 표시도 없다.

| 키 | 동작 |
|---|---|
| `]` | 5%씩 확대 (최대 200%) |
| `[` | 5%씩 축소 (최소 50%) |
| `\` | 100% 로 되돌리기 (한글 입력 상태의 `₩` 도 먹는다) |

- 배율은 `:root` 의 `--zoom` 하나이고 `.slide` 에만 `transform:scale(var(--zoom,1))` 로 걸린다. 헤더·푸터는 제자리다.
- `.slide` 폭이 `min(1280px, calc(100% / var(--zoom,1)))` 이라 **확대해도 좌우로 잘리지 않는다.**
- 실제로 쓰는 범위는 **100~140%**. 그 이상은 도해가 많은 장에서 위아래가 잘린다.
- 슬라이드 밖(헤더·푸터)에 본문을 두지 않는다. 배율이 걸리는 것은 `.slide` 뿐이다.
- `@keyframes enter` 두 프레임에 `scale(var(--zoom,1))` 이 들어 있어야 한다. 빼면 장을 넘길 때마다 100%로 튄다.

## 6. 기존 덱을 고칠 때

인터뷰를 처음부터 다시 돌리지 않는다. **고칠 장과 이유만 받는다.**

### 6-0. 사용자가 브라우저에서 고친 것을 묻지 않는다 — 먼저 지킨다

사용자는 덱을 브라우저에서 직접 고친다. 에이전트가 그걸 모르고 고치면 사용자 편집이 묻힌다.
원인은 셋이다. 셋 다 막는다.

| 원인 | 에이전트가 할 일 |
|---|---|
| 편집이 브라우저에만 있고 파일에 없다 | **덱은 항상 저장 서버로 연다**(3절 5번). 그러면 고치는 즉시 파일에 들어가 묻지 않아도 된다. file:// 로 열려 있던 덱이면 서버로 다시 열고, 그 전에 `⌘S` 를 한 번 부탁한다 |
| 에이전트가 예전 원본(스크래치패드의 조각, 템플릿)으로 덱을 **다시 빌드**한다 | 하지 않는다. 고칠 때마다 **디스크의 현재 파일을 새로 읽고, 그 장만 부분 치환**한다. 기억 속 내용으로 장을 통째로 다시 쓰지 않는다 |
| 사용자가 에이전트 수정 **전에** 열어 둔 탭에서 계속 고치고 저장한다 | 저장 서버로 연 탭은 알아서 새로고침한다. 고친 뒤 `open` 으로 새 탭을 또 띄우지 않는다 — 같은 덱 탭이 둘이면 헷갈린다. file:// 탭이면 새로고침을 부탁한다 |

- 치환할 때는 바꿀 문자열이 파일에 **정확히 한 번** 있는지 확인하고(`assert count==1`), 없으면 멈추고 다시 읽는다.
  사용자가 그 문장을 이미 고쳤다는 뜻이다. 사용자 문장을 기준으로 다시 맞춘다.
- `.slide` 순서를 바꾸면 저장 안 한 편집의 자리 번호가 밀린다. 템플릿이 원래 글자로 자리를 다시 찾지만, 장을 넣거나 빼기 전에는 6-0 첫 줄을 꼭 말한다.

- 모션이 걸린 장은 편집을 켜면 모션이 걷히고 원래 마크업만 보인다. 에이전트도 원래 마크업 기준으로 고친다.
- 그 덱이 어떤 스타일인지 먼저 확인하고(`--paper` 값·클래스 이름), 그 `style.md` 를 읽고 나서 고친다.
- 장을 새로 끼워 넣을 때도 2-5 사다리 점검을 다시 돌린다.
- 스타일별 주의사항은 각 `style.md` 마지막 절에 있다.

## 7. 이미지 넣기

외부 요청 0건이 원칙이므로 스크린샷은 **base64 data URI 로 인라인**한다.

```bash
python3 - <<'PY'
import base64,pathlib
p=pathlib.Path("스크린샷.png")
print("data:image/png;base64,"+base64.b64encode(p.read_bytes()).decode())
PY
```

- 폭 1600px 이하로 줄여서 넣는다. 이미지 3장이면 파일이 1.2MB 가 된다.
- **before 이미지는 죽인다**: 감싸는 요소에 `class="fade"` (`opacity:.52; grayscale(.45)`).
  두 장을 나란히 놓고 한쪽을 흐리게 하는 것으로 "이쪽을 보라"를 말한다.
- **스크린샷과 도표는 다른 부품이다.** 스크린샷(앱 화면)은 `.shot`·`.frame` — 왼쪽 위 기준으로 *잘라* 보여 준다.
  공식 문서 도표·다이어그램처럼 **전체가 보여야 하는 그림**은 `.figure` — 자르지 않고 가운데에 놓는다.
  `.frame` 으로 도표를 넣으면 그림이 잘리거나 왼쪽으로 쏠린다.

## 8. macOS 한글 파일명 주의

macOS 의 한글 파일명은 **NFD(자모 분리)** 로 저장된다.
`find -name "*발표*"` 처럼 **와일드카드 패턴에 한글을 넣으면 0건**이 나오고, 그게 에러가 아니라 통과처럼 보인다.

- 셸: `find "{폴더}" -name "*.html"` — 패턴에 한글을 넣지 않는다.
- 경로를 정확히 적는 것(`cat "{폴더}/파일.html"`)은 잘 된다.
