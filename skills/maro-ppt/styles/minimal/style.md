# 최소 덱 (minimal)

> **아이보리 종이 바탕 · 각진 흰 카드 · 라임 형광펜 한 획**

세 가지가 인상의 전부다. 전체 규격은 같은 폴더의 `design-spec.md` 에 있다.

---

## 1. 절대 어기지 않는 것

```css
--paper:#f4f1e9;   /* ① 배경은 흰색이 아니라 아이보리 */
--ink:#17231d;     /* ② 검정이 아니라 짙은 초록빛 잉크 */
--lime:#c9f450;    /* ③ 강조색은 이 하나뿐 */
```

**④ 본문 제목은 그 장의 내용을 그대로 쓴다. 후킹은 표지에서 이미 했다.**

```html
<h1>MCP 서버의 <span class="accent">세 가지 구성요소</span></h1>
<h1>API 방식의 <span class="accent">한계</span></h1>
<h2>연결 비용 <span class="accent">N×M vs N+M</span></h2>
```

- **한 줄, 명사구가 기본이다.** 그 장에서 다루는 것을 이름으로 부른다.
- **본문에서 쓰지 않는 것**: 반문("왜 자꾸 헷갈릴까?"), 반전("질문이 틀렸다"),
  조건+주장 2단 구성, 감탄·과장. 주장은 제목이 아니라 **리드 한 문장과 결론 밴드**가 한다.
- **예외는 표지 한 장뿐이다.** 표지 `h1` 에는 인터뷰에서 받은 후킹 제목을 그대로 건다.
- 형광펜 `.accent` 는 제목의 **핵심 명사**에 건다. `linear-gradient(transparent 64%,var(--lime) 64%)`.
  **한 장에 한 번만.** 두 번 쓰면 강조가 사라진다 — 이쪽이 진짜 규칙이다.
- `<br>` 로 직접 끊은 줄에만 `.nowrap` 을 붙인다. 한 줄 제목에는 필요 없다.
- 제목 자간 `-.048em` 을 건드리지 않는다.

**⑤ 구조는 각지고, 예시 UI만 둥글다.**

| 대상 | radius | 색 |
|---|---|---|
| 카드·밴드·프레임·프롬프트 | **0** | 흰 면 + `1px var(--line)` |
| 슬라이드 안에 그린 "제품 버튼·진행 막대" | 6~12px / 999px | `--blue` |

파랑·라운드·알약은 *덱의 스타일이 아니라 인용된 제품의 스타일*이다. 덱 자신의 구조에 쓰지 않는다.

**⑥ 태그를 쓰지 않는다.** `.chip` / `.chips` 는 폐기됐다.
주제를 태그로 나열하면 관계가 안 보이고 단어만 훑게 된다.

## 2. 레이아웃

| 그 장이 하려는 것 | `<section class="…">` |
|---|---|
| 글과 그림이 짝을 이룬다 (정의+흐름, 비교, 절차) | `slide two dense` |
| 도해가 넓게 펼쳐져야 한다 (3열 카드, 벤, 숫자 히어로, 스크린샷) | `slide one` |
| 표지 | `slide title` |

한 장의 형태:

```
h1 / h2   — 핵심 명사에 .accent (한 장에 한 번)
p.body    — 1문장. 제목을 풀어 주는 한 줄
────────
도해 하나
결론 밴드 한 줄
```

## 3. 도해 카탈로그

무엇을 놓을지는 **말하려는 관계**로 정한다. 예쁜 것으로 정하지 않는다.

| 말하려는 것 | 쓰는 것 | 클래스 |
|---|---|---|
| 순서·인과 | 화살표 흐름 3칸 (마지막 칸만 잉크) | `.flow` |
| A와 B의 차이 | 2열 카드 + 아래 잉크 펀치라인 | `.duo` + `.band.full` |
| 구성요소 셋 | 상단 5px 잉크 바 카드 3개 | `.trio` + `.card.top` |
| 절차 | 원형 번호 목록 | `.steps` |
| 두 집합의 관계 | 겹치는 원 두 개 (교집합만 라임) | `.venn` |
| 수치 대비 | 큰 숫자 두 개 (전은 회색, 후는 형광펜) | `.stat` |
| 그대로 칠 프롬프트 | 어두운 모노 블록 + 라임 레일 | `.prompt` |
| 화면 증거 | 검은 프레임 + 오프셋 그림자 | `.shot` / `.frame` |
| 구조·연결 (여러 요소가 화살표로 얽힘, 4~8개) | 박스 + 화살표 도식. **발표 중에 끌어서 고칠 수 있다** | `.dg` (3-1) |

`.flow` 는 한 줄로 흐르는 3칸까지다. 갈라지거나 합쳐지거나 되돌아오면 `.dg` 로 간다.
`.dg` 는 한 덱에 **2장까지.** 도식이 많으면 설명이 아니라 설계서가 된다.

**도해는 결론 밴드 한 줄로 닫는다.** 그림만 놓고 넘어가지 않는다.

```html
<div class="band">{결론 문장}<b>{숫자}</b></div>   <!-- 잉크: 성과·결론 -->
<div class="band lime">{판단 기준 한 줄}</div>       <!-- 라임: 전제·비용·주의 -->
```

밴드는 덱 전체에서 **6개 이하**, 프롬프트 블록은 **2개 이하**로 쓴다. 남발하면 무게가 사라진다.

템플릿에 없는 유형이 필요하면 `design-spec.md` 6-3 의 15장 골격에서 가져온다.

### 3-1. 도식 `.dg` — 좌표로 놓는 박스와 화살표

템플릿 10번 장이 견본이다. 캔버스는 고정 px 좌표계이고, 폭이 좁으면 스크립트가 통째로 줄인다.

```html
<div class="dg" data-size="1180x380">                    <!-- slide one 기준. two 의 오른쪽 칸이면 640x440 -->
  <div class="dg-node" id="dg-a" style="left:0px;top:130px;width:230px;height:120px">
    <b>{이름}</b><span>{한 줄 설명}</span></div>
  <div class="dg-node ink" id="dg-d" style="…"><b>{결론 박스}</b><span>…</span></div>
  <div class="dg-edge" data-from="dg-a" data-to="dg-d" data-label="{동작}"></div>
</div>
<div class="band lime">{이 구조에서 봐야 할 곳 한 줄.}</div>
```

| 요소 | 규칙 |
|---|---|
| `.dg-node` | `id` 필수(덱 전체에서 유일, `dg-` 로 시작). 인라인 `left/top/width/height` 필수. 좌표는 10의 배수 |
| 박스 색 | 기본 흰 카드 · `.ink` 결론 박스(한 도식에 1개) · `.lime` 강조(한 도식에 1개까지) |
| `.zone` | 묶음 배경판. 윗줄 `<b>` 가 묶음 이름. **DOM 에서 다른 박스보다 앞에** 둔다 |
| `.ghost` | 테두리 없는 캡션 |
| `.dg-edge` | 빈 div. `data-from/to` = 박스 id. 옵션 `data-label` · `data-style="dashed"` · `data-tone="muted"`(보조 흐름) · `data-curve`(-.5~.5) · `data-arrow`(end·both·none) |
| 글자 크기 | 박스 제목 17px · 설명 13px 가 하한이다. 캔버스가 축소되면 더 작아지니 박스를 줄이지 말고 개수를 줄인다 |

- 화살표 그림(SVG)은 저장하지 않는다. `.dg-edge` 데이터만 저장하고 열 때마다 새로 그린다.
- 글자는 박스 안 HTML 에 둔다. 화살표 라벨도 HTML(`.dg-label`)이다. SVG `<text>` 금지는 그대로다.
- 두 박스 사이 왕복 화살표는 한쪽에 `data-curve=".25"`, 다른 쪽에도 `.25` 를 준다(진행 방향 기준이라 서로 반대로 휜다).
- 도식도 **결론 밴드로 닫는다.**

## 4. 쓰기 규칙 (이 스타일 고유)

- 본문 제목에 마침표를 찍지 않는다. 물음표도 쓰지 않는다(1-④).
- 리드 `.body` 는 **한 문장**. 두 문장을 넘기면 제목이 틀린 것이다.
- 담백한 한국어. 과장·감탄사·마케팅 문구 금지. (후킹은 표지에서 끝났다)
- 장식용 이모지 금지. `→ ↗ ✓ ① 01` 같은 기능 기호만.
- 외부 링크는 `이름 ↗` 형태의 텍스트 링크로.

## 5. 완료 전 체크

```
□ 배경이 #f4f1e9 인가 (흰색이 아닌가)
□ 후킹이 표지 한 장에만 있고, 본문 제목은 명사구인가
□ 제목마다 .accent 가 한 번씩만 걸렸는가
□ 직접 끊은 제목 줄이 .nowrap 으로 감싸였는가
□ 마무리 장에 핵심 메시지가 문장 그대로 놓였는가
□ 카드·밴드의 radius 가 0 인가
□ 태그(.chip / .chips)를 쓰지 않았는가
□ 라운드·파랑·알약이 예시 UI 안에만 있는가
□ 그림자가 스크린샷 프레임 외에 없는가
□ 각 도해가 결론 밴드로 닫히는가 (밴드 합계 6개 이하)
□ 프롬프트 블록이 2개 이하인가
□ 900px·600px 로 줄여도 1단으로 접히는가
□ 도식이 2장 이하이고, 박스 id 가 덱 전체에서 겹치지 않는가
```

(공통 요건 체크는 SKILL.md 5절에 있다. 둘 다 돌린다)

검증:

```bash
f="{만든 파일}"
grep -c 'class="slide'            "$f"   # 장수
grep -o 'class="accent'           "$f" | wc -l   # 장수와 비슷해야 정상
grep -o 'class="band'             "$f" | wc -l   # 6 이하
grep -oE '[✨🚀🎯💡🔥]'            "$f"   # 비어야 정상
grep -oE 'class="dg-node[^"]*" id="[^"]+"' "$f" | grep -oE 'id="[^"]+"' | sort | uniq -d   # 비어야 정상 (박스 id 중복)
```

## 6. 이 스타일로 만든 덱을 고칠 때

- 오래 고쳐 쓴 덱은 CSS 패치가 아래로 쌓여 있다. **뒤에 오는 선언이 정답**이다.
  또 패치를 아래에 쌓지 말고 해당 선언을 찾아 고친다.
- `.slide:nth-of-type(n)` 으로 특정 장을 겨냥한 규칙은 **장 순서가 바뀌면 깨진다.** 클래스 이름을 붙인다.
