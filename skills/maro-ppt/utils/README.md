# 유틸

**유틸은 슬라이드 안에 들어가는 에셋이다.** 스타일이 *덱이 어떻게 보이는가*를 정한다면,
유틸은 *슬라이드 한 칸에 무엇을 그려 넣는가*를 정한다.

한 폴더가 한 유틸이다. **여기에 폴더를 추가하면 확장 엔진이 자동으로 후보에 넣는다.**

```
utils/
├── README.md
└── kakao-chat/         ← 유틸 하나
    └── util.md         ← 필수. frontmatter + CSS + 마크업 + 대사 쓰는 법
```

---

## 등록된 유틸

| 폴더 | 이름 | 보여 주는 것 | 언제 |
|---|---|---|---|
| `kakao-chat` | 카카오톡 채팅 화면 | 주고받은 대화, 그때의 온도 | 상황을 재현해야 할 때 |

---

## 유틸은 스타일과 무관하다

유틸은 **인용된 제품·현실의 화면**이다. 덱의 스타일을 따르지 않고 *그 제품처럼* 생겨야 한다.
카톡 목업은 어느 스타일의 덱에 놓이든 카톡처럼 생기면 된다.

minimal 스타일에 이미 있는 규칙이 이것을 뒷받침한다.

> 파랑·라운드·알약은 *덱의 스타일이 아니라 인용된 제품의 스타일*이다. 덱 자신의 구조에 쓰지 않는다.

그래서 **유틸은 한 벌만 만들면 모든 스타일에서 쓰인다.** 스타일마다 만들지 않는다.

다만 유틸이 덱에 **얹히는 방식**은 스타일이 정한다 — 어느 칸에 놓이고, 무엇으로 닫히는지.
minimal 에서는 결론 밴드 한 줄로 닫는다.

---

## 도해와 무엇이 다른가

| | 도해 (스타일의 카탈로그) | 유틸 |
|---|---|---|
| 무엇 | 관계를 **추상화한 그림** | 현실 화면의 **재현** |
| 예 | `.flow` `.duo` `.venn` `.stat` | 카톡 화면, 브라우저 창, 터미널 |
| 어디 정의 | `styles/{스타일}/style.md` | `utils/{유틸}/util.md` |
| 스타일마다 | 다르다 | 같다 |

**"A와 B는 다르다"는 도해가 낫다. "그래서 이런 일이 벌어졌다"는 유틸이 낫다.**

## 새 유틸 추가하는 법

**1. 폴더를 만든다.** 이름은 소문자·하이픈만. (`utils/{이름}/`)

**2. `util.md` 를 쓴다.** frontmatter 는 확장 엔진이 읽는 곳이라 형식을 지킨다.

```markdown
---
util: {폴더 이름과 같게}
label: {한국어 이름}
shows: {무엇을 보여 주는가}
when: {언제 쓰나 — 확장 엔진이 이 문장으로 매칭한다. 가장 중요하다}
slot: {어느 칸에 들어가나}
needs: {채워야 할 데이터}
---
```

본문에는 최소한 이 다섯 가지를 쓴다. `kakao-chat/util.md` 를 베끼는 게 빠르다.

| 절 | 쓸 것 |
|---|---|
| 언제 쓰나 | **쓴다 / 쓰지 않는다** 를 갈라서. 남용 상한도 여기 |
| 붙이는 법 | 그대로 복사할 CSS 한 덩이 + 마크업 골격 |
| 내용 쓰는 법 | 이 유틸 안의 글을 어떻게 쓰는지 |
| 지켜야 할 것 | 편집 가능 선택자 · 외부 요청 0건 · 무엇으로 닫는지 |
| 완성 예 | 실제로 채운 것 하나 통째로 |

**3. 공통 요건을 만족시킨다.**

```
□ 글자가 편집 대상 선택자(p · small · h3 · .band …) 안에 있는가
□ 외부 요청 0건인가 (이미지·아이콘 파일·웹폰트 없음 — 색과 도형으로 그린다)
□ SVG <text> 를 쓰지 않았는가
□ 900px·600px 에서 깨지지 않는가
□ 한 덱에 몇 번까지 쓸지 상한을 정했는가
```

**4. 이 README 의 "등록된 유틸" 표에 한 줄 추가한다.**
