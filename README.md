# 몸값 올리는 PPT 제작 스킬 (`maro-ppt`)

발표 자료를 **질문으로 시작해서 설득 구조로 끝내는** Claude Code 스킬입니다.

결과물은 **자립형 단일 HTML 파일** 하나입니다.
외부 요청 0건 — 웹폰트도 CDN도 없습니다. 파일 하나만 들고 다니면 어디서든 열립니다.

---

## 시작하면 이렇게 물어봅니다

한 번에 하나씩 묻습니다. 앞의 답이 뒤의 질문을 바꾸기 때문입니다.

**1. 핵심 메시지** — "듣고 난 사람이 한 문장만 기억한다면?"

주제가 아니라 **주장**이어야 합니다. 판정법은 반대 문장을 만들어 보는 것입니다.

| 답 | 판정 |
|---|---|
| "토큰에 대해서" | ✗ 반대 문장이 없습니다. 주제입니다 |
| "토큰을 모르면 API 비용이 10배로 샌다" | ✓ 주장입니다 |

이 한 문장이 덱의 척추가 됩니다. 표지 부제로 한 번, 마지막 장 결론 밴드로 한 번 더 나옵니다.

**2. 후킹 제목** — 없으면 핵심 메시지에서 손실형·숫자형·오해형 세 개를 뽑아 드립니다.

**후킹은 표지 한 장에서만 합니다.** 본문 제목까지 후킹하면 장끼리 경쟁해서 덱 전체가 난잡해집니다.
본문은 명사구로 그 장의 내용을 그대로 부릅니다.

**3. 슬라이드 구성** — 다룰 항목을 순서대로. 거칠어도 됩니다. 위에서 본 대로 펼쳐집니다.

**4. PPT 스타일** — 등록된 스타일이 둘 이상이면 이름과 인상을 나란히 보여 주고 고르게 합니다.

**5. 나머지** — 듣는 사람, 저장 위치. 장수는 묻지 않습니다.

## 만들고 나서

바로 HTML을 만들어 열어 주고, 장별 한 줄 요약 표를 같이 보여 줍니다.
마음에 안 드는 장 번호만 말하면 그 장만 고칩니다.

```
01 표지    모르면 새는 돈, 토큰
02 도입    같은 질문에 다른 요금        .stat
03 정의    토큰은 모델이 읽는 조각      .flow
04 예시    한국어와 영어의 토큰 수      .duo
```

## 스타일

**PPT 스타일도 인터뷰에서 고릅니다.** 등록된 스타일이 하나뿐이면 묻지 않고 알려만 줍니다.

현재 등록된 스타일:

### `minimal` — 최소 덱

> **아이보리 종이 바탕 · 각진 흰 카드 · 라임 형광펜 한 획**

세 가지가 인상의 전부입니다.

| | |
|---|---|
| 바탕 | `#f4f1e9` — 흰색이 아닙니다 |
| 구조 | `border-radius: 0`, 그림자 없음, 1px 선 |
| 강조 | 라임 `#c9f450` 하나. 제목의 핵심 명사에 한 획 |

파랑·라운드·알약은 슬라이드 안에 **그려 넣은 예시 UI**에만 씁니다. 덱 자신의 구조에는 쓰지 않습니다.

규격 전문은 [`styles/minimal/design-spec.md`](skills/maro-ppt/styles/minimal/design-spec.md),
브라우저로 보려면 [`design-spec.html`](design-spec.html) 을 열면 됩니다.

### 스타일 추가하기

`skills/maro-ppt/styles/` 에 **폴더 하나를 추가하면 인터뷰 선택지에 자동으로 뜹니다.**

```
styles/{이름}/
├── style.md        ← frontmatter(label·tagline·fit) + 규칙 5절
└── template.html    ← 공통 요건(외부 요청 0건·인라인 편집·화면 배율)을 만족할 것
```

**확장 엔진은 스타일과 무관합니다.** 스타일이 바꾸는 것은 *어떻게 보이는가*이지
*무엇을 몇 장으로 말하는가*가 아닙니다. 스타일마다 다른 것은 **도해 카탈로그** 하나뿐이라,
확장 엔진이 "순서·인과를 말해야 한다"까지 정하면 그것을 무엇으로 그릴지는 그 스타일의 표가 정합니다.

자세한 것은 [`styles/README.md`](skills/maro-ppt/styles/README.md) 에 있습니다.

## 유틸

**유틸은 슬라이드 안에 들어가는 에셋입니다.** 스타일이 *덱이 어떻게 보이는가*를 정한다면,
유틸은 *슬라이드 한 칸에 무엇을 그려 넣는가*를 정합니다.

| 폴더 | 이름 | 언제 |
|---|---|---|
| `kakao-chat` | 카카오톡 채팅 화면 | 상황을 재현해야 할 때 |

**말하지 않아도 알아서 넣습니다.** "그래서 이런 일이 벌어졌다"를 말하는 장이면
설명 카드 대신 그 상황이 실제로 벌어진 화면을 넣고, 생성 후 요약표에 표시합니다.
빼달라고 하면 뺍니다. 한 덱에 2개까지가 상한입니다.

```
02 도입    링크를 보냈는데 안 열린다     ★ kakao-chat
03 정의    배포는 남의 컴퓨터로 옮기는 일  .flow
```

**도해와는 다릅니다.** 도해(`.flow` `.duo` `.venn`)는 관계를 추상화한 그림이고,
유틸은 현실 화면의 재현입니다. "A와 B는 다르다"는 도해가, "그래서 이런 일이 벌어졌다"는 유틸이 낫습니다.

**유틸은 스타일과 무관합니다.** 인용된 제품의 화면이라 덱 스타일을 따르지 않고 그 제품처럼 생기면 됩니다.
그래서 한 벌만 만들면 모든 스타일에서 쓰입니다. 추가하는 법은
[`utils/README.md`](skills/maro-ppt/utils/README.md) 에 있습니다.

## 만든 덱으로 할 수 있는 것

결과 HTML에는 발표 중에 쓰는 기능이 들어 있습니다.

| 기능 | 키 |
|---|---|
| 장 넘기기 | `←` `→` |
| **글자 직접 고치고 파일에 덮어쓰기** | `E` 로 편집 켜고 `⌘S` 로 저장 |
| **도식 고치기** | 편집을 켠 채 도식 장에서 박스를 끌기 · 더블클릭으로 글자 · `[연결]` `[모양]` `[휘기]` |
| **강의 중 화면 배율** | `]` 확대 / `[` 축소 / `\` 원래대로 |
| **발표용 파일 만들기** | 마지막 장의 `[편집 기능 삭제]` |

- 편집은 클릭해서 타이핑하면 됩니다. 서식과 구조는 안 바뀝니다.
- **고치는 즉시 원본 파일에 저장됩니다.** 스킬은 덱을 내장 저장 서버로 엽니다.
  ```bash
  python3 ~/.claude/skills/maro-ppt/tools/serve.py --open "덱.html"   # 끄기: --stop
  ```
  서버는 `127.0.0.1` 에서만 듣고, 홈 폴더 아래 `.html` 만 읽고 씁니다.
- **에이전트와 같이 고쳐도 편집이 묻히지 않습니다.**
  - 에이전트가 파일을 고치면 열린 탭이 알아서 새로고침해 그 변경을 받습니다(보던 장 유지).
  - 저장이 겹치면 서버가 거절하고, 탭은 새로 받은 파일에 내 편집을 원래 글자 기준으로 다시 붙여 저장합니다.
- 서버 없이 파일을 직접 열었으면 `⌘S` 로 저장합니다(File System Access API — 처음 한 번만 파일을 묻고 그 뒤로는 자동 저장).
- 배율은 뒷자리에서 글씨가 안 보일 때 쓰는 조작입니다. 버튼도 표시도 없습니다.

## 설치

### 플러그인으로 (권장)

```
/plugin marketplace add https://github.com/RDDcat/maro-ppt
/plugin install maro-ppt@maro-ppt
```

### 스킬만 직접 복사

```bash
git clone https://github.com/RDDcat/maro-ppt.git
cp -R maro-ppt/skills/maro-ppt ~/.claude/skills/
```

프로젝트 하나에만 쓰려면 `~/.claude/skills/` 대신 그 프로젝트의 `.claude/skills/` 로 복사합니다.

## 쓰는 법

설치하고 나서 그냥 말하면 됩니다.

```
발표 자료 만들어줘
{주제} 강의 슬라이드 만들어줘
```

또는 직접 부릅니다.

```
/maro-ppt
```

손으로 만들 때는 [`skills/maro-ppt/styles/minimal/template.html`](skills/maro-ppt/styles/minimal/template.html) 을 복사해
`{중괄호}` 자리를 채우고, 필요 없는 `<section class="slide">` 은 통째로 지웁니다.
헤더의 장수는 자동으로 세어집니다.

---

## 이 스킬을 쓰지 않는 곳

- **1280×720 고정 캔버스 · 인쇄용 PDF**가 필요한 경우. 이 덱은 뷰포트 반응형이라 인쇄 규격이 다릅니다.
- **읽는 문서**. 이 덱은 한 장에 메시지 하나를 놓는 구조라, 읽어야 하는 분량은 담기지 않습니다.
